# 5. 顶部一级分类怎么增加/删除

顶部模块由 `_menu_defs/*.md` 中这些字段控制：

```yaml
module_key: project
show_top: true
top_label: 项目
top_url: /
top_order: 10
```

含义：

```text
show_top: true     显示在顶部
show_top: false    不显示在顶部
top_label          顶部显示名称
top_url            点击后的页面
top_order          排序，数字越小越靠左
```

注意：新增一个全新一级模块，不只是增加菜单文字，还必须有对应页面。

例如新增“视频”为顶部模块，需要：

1. `_menu_defs/videos.md` 设置 `show_top: true`
2. `top_label: 视频收藏`
3. `top_url: /videos/`
4. 保存并发布

现有视频页面已经存在，所以可以直接这样提升到顶部。

# 7. 文章里插入图片

文章图片建议存放：

```text
assets/images/<文章对应文件夹>/
```

Typora 当前使用相对路径规则。

Markdown 图片示例：

```md
![数据链路图](/assets/images/example/data-lineage.jpg)
```

原则：

- 文件名优先英文、数字、短横线
- JPG 用于截图/照片
- PNG 用于文字流程图、透明图
- 大图片尽量压缩，避免网页加载慢

# 13. 右侧“个人收藏”怎么增加模块

配置目录：

```text
_collection_defs/
```

当前：

```text
_collection_defs/
├─ gallery.md
└─ videos.md
```

新增“游戏收藏”示例：

新建：

```text
_collection_defs/games.md
```

内容：

```yaml
---
key: games
title: 游戏收藏
description: 喜欢的游戏与攻略
public_url: /games/
icon: "🎮"
order: 30
---
```

重要：

**必须使用 `public_url`，不要使用 `url`。**

Jekyll Collection Document 的 `url` 是保留属性，之前曾因此生成 `/collection_defs/gallery` 错误地址并导致 404。

同时必须确保 `/games/` 页面真实存在，否则点击仍会 404。

# 19. `.github/workflows/pages.yml` 是什么

GitHub Pages 自动部署工作流。

每次 push 到 `main` 后会：

```text
Checkout
→ Jekyll 构建
→ verify-site.py 检查
→ 上传 Pages 构建产物
→ 部署
```

工作流采用：

```yaml
cancel-in-progress: true
```

因此连续提交时只保留最新部署，避免中间半成品排队上线。

# 21. 发布前站点检查

`_scripts/verify-site.py` 会检查核心路由：

```text
/
/404.html
/articles/
/bank/
/manufacturing/
/ecommerce/
/sql-hive/
/python/
/git/
/nav/
/music/
/gallery/
/videos/
/search/
```

核心页面缺失时，不允许坏版本覆盖线上网站。

同时禁止把内部配置路径发布成可点击地址，例如：

```text
/collection_defs/
/menu_defs/
```

普通历史坏链接只输出 WARNING，不会因为一个普通链接把整个网站卡死。

# 22. 同步博客.bat

用途：

```text
GitHub → 本地
```

它会：

1. 检查 Git
2. 自动检测 Windows 代理
3. 检查本地是否有未提交修改
4. 测试 GitHub 网络
5. `git pull --rebase origin main`

如果检测到本地未提交文件，它会停止，避免把本地内容冲掉。

此时：

- 本地内容需要保留 → 运行 `发布博客.bat`
- 本地内容不要了 → 删除/还原后再同步

# 23. 发布博客.bat

用途：

```text
本地 → GitHub → GitHub Pages
```

流程：

```text
自动代理
→ git add -A
→ git commit
→ 测试 GitHub
→ git pull --rebase
→ git push
→ GitHub Actions 自动部署
```

如果出现 `CONFLICT`：

**不要随意删除文件，不要强制 push。**

保留窗口并处理冲突。

---

# 24. GitHub Actions 怎么看是否发布成功

GitHub 仓库：

```text
Actions
→ Deploy Jekyll site to Pages
```

状态：

```text
绿色 ✅ = 发布成功
红色 ❌ = 构建/检查失败，不要继续大改，先看错误
黄色/转圈 = 正在部署
灰色取消 = 被更新的提交取代，通常正常
```

因为启用了只保留最新部署，所以连续修改时旧任务被取消是正常现象。

# 25. 404 怎么处理

404 页面会显示：

```text
当前访问地址：/具体错误路径
```

看到 404 时先记录这个地址。

常见原因：

1. 链接写错
2. 页面还没有创建
3. 配置文件内部路径被误当成公开链接
4. 旧地址已经变化

目前个人收藏使用 `public_url`，不要改回 `url`。

# 26. 推荐的文件维护原则

以后只遵循这几条：

1. 正式文章只进 `_posts/`
2. 模板和草稿只进 `_drafts/`
3. 分类只改 `_menu_defs/`
4. 网址/歌曲/图片/视频内容只改 `_data/`
5. 个人收藏模块只改 `_collection_defs/`
6. 本地媒体统一放 `assets/`
7. 核心代码 `_layouts/`、`_includes/` 平时不要碰
8. 写之前同步，写完发布
9. GitHub Actions 绿色后再确认线上效果
10. 大图片和视频注意体积，能懒加载就不要首屏全加载
